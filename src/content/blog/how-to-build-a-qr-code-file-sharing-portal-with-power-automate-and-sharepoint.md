---\ntitle: How to Build a QR Code File Sharing Portal with Power Automate and SharePoint\ndescription:Learn how to build a QR-code file sharing portal using Power Automate, SharePoint, shareable links, QR images, tracking lists and notifications.\npubDate: 2026-09-10\nlabel: Power Automate\n---\n\n# <p>A QR-code file portal can make it easy for external users, field teams, or visitors to open the latest document without navigating through a complicated folder structure.</p><p>A practical solution can combine SharePoint, Power Automate, a QR-code service, and a public or externally accessible file link.</p><h2>The basic workflow</h2><p>The process starts when a PDF or other approved file is added. Power Automate creates or retrieves a shareable URL, generates a QR code from that URL, saves the QR image, and records the information in a tracking list.</p><h2>Use a master and detail structure</h2><p>For larger solutions, a parent list can track each request or batch while a child list stores the individual files.</p><p>The parent list might contain a title, status, attachment count, and created date. The child list can contain the parent ID, file name, file URL, file ID, QR image, and processing status.</p><h2>Generate the shared link first</h2><p>The QR code should point to a stable URL. If the original file location requires authentication that external users do not have, the QR code will not solve the access problem.</p><p>Create the correct externally accessible link before generating the QR image.</p><h2>Generate the QR code</h2><p>Many QR-code services accept a URL as a query parameter and return a PNG image. Power Automate can call that service with an HTTP action, then save the returned image to a document library.</p><p>Always encode the destination URL correctly before sending it to the QR service.</p><h2>Store the QR image separately</h2><p>Keeping generated QR images in a dedicated folder makes the solution easier to manage. Use predictable filenames so each QR image can be traced back to its source file.</p><h2>Save tracking information</h2><p>Store the original file name, shareable URL, QR image location, processing status, and related identifiers in a SharePoint list.</p><p>This creates a searchable history and makes it easier to rebuild or replace a QR image later.</p><h2>Display the QR code in Teams or email</h2><p>Once the image is available, you can include it in a Teams adaptive card or email notification along with the file name and a clickable link.</p><p>For adaptive cards, make sure the image source is accessible to the recipient. If required, use hosted content or another supported method rather than a private image URL.</p><h2>Handle failures clearly</h2><p>Use status values such as Processing, Completed, and Failed. If the shared-link step fails, do not continue to generate a QR code that points nowhere.</p><p>Scopes and run-after settings can help separate normal processing from error handling.</p><h2>Think about link security</h2><p>External sharing should match your organization's security policy. A public QR code is only as secure as the destination URL behind it. Use expiration, restricted sharing, or other controls when the file should not remain publicly accessible indefinitely.</p><h2>Final thoughts</h2><p>The QR code itself is the easy part. The real design challenge is creating a reliable file-sharing workflow behind it. Build the process around stable links, clear status tracking, predictable storage, and appropriate access controls.</p>\
