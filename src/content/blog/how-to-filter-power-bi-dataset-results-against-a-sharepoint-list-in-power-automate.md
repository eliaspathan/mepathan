---\ntitle: How to Filter Power BI Dataset Results Against a SharePoint List in Power Automate\ndescription:Learn how to filter Power BI dataset query results against SharePoint records in Power Automate using Filter Array, composite keys and firstTableRows.\npubDate: 2026-09-10\nlabel: Power Automate\n---\n\n# <p>When you use <strong>Run a query against a dataset</strong> in Power Automate, the result is usually an array of objects. A common requirement is to compare those Power BI rows with records from a SharePoint list and keep only the matching records.</p><p>This article shows a practical way to do that with <strong>Filter array</strong> and a composite key.</p><h2>Example Power BI output</h2><pre><code>[
  {
    "Projects[Project_Number]": "P1",
    "Projects[Project_Name]": "ABC",
    "[Project_Key]": "P1ABC"
  },
  {
    "Projects[Project_Number]": "P2",
    "Projects[Project_Name]": "EFG",
    "[Project_Key]": "P2EFG"
  }
]</code></pre><h2>Get the rows from the Power BI action</h2><p>For many Power BI query actions, Make sure you pass the rows array—not an individual row—to Filter array. If <code>firstTableRows</code> is available, use:</p><pre><code>outputs('Run_a_query_against_a_dataset')?['body/firstTableRows']</code></pre><p>If you are working with the full nested response, the equivalent path is:</p><pre><code>body('Run_a_query_against_a_dataset')?['results']?[0]?['tables']?[0]?['rows']</code></pre><p>The <code>[0]</code> values select the first result and first table containers. They do not select the first data row.</p><h2>Use a composite key</h2><p>If Project Number alone is not unique enough, create a key from multiple fields. For example:</p><pre><code>Project_Number + Project_Name</code></pre><p>The Power BI result and SharePoint list should use the same key format.</p><h2>Filter the Power BI array</h2><p>Set the <strong>From</strong> property of Filter array to the Power BI rows array. Inside the condition, reference the current Power BI row with:</p><pre><code>item()?['[Project_Key]']</code></pre><p>Then compare it with the corresponding SharePoint key:</p><pre><code>equals(
    item()?['[Project_Key]'],
    &lt;SharePoint Project_Key&gt;
)</code></pre><h2>Normalize keys when necessary</h2><p>Differences in capitalization or spaces can prevent otherwise identical keys from matching. A useful normalization pattern is:</p><pre><code>toUpper(trim(item()?['[Project_Key]']))</code></pre><p>Apply the same normalization to the SharePoint value before comparing them.</p><h2>Get the first matching record</h2><p>If only one matching Power BI row is expected, you can retrieve it after Filter array with:</p><pre><code>first(body('Filter_array'))</code></pre><p>Before using the first record, you can check whether the filtered array is empty:</p><pre><code>empty(body('Filter_array'))</code></pre><h2>Why this approach is useful</h2><p>This pattern keeps the Power BI query result as an array and lets Power Automate perform the comparison without unnecessarily transforming every row first. It works well for synchronizing dataset results with SharePoint lists, validating records, and identifying rows that should be inserted or updated.</p>\
