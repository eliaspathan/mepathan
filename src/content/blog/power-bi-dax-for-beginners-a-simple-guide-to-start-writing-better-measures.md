---\ntitle: Power BI DAX for Beginners: A Simple Guide to Start Writing Better Measures\ndescription:Learn the essential DAX concepts for Power BI beginners, including measures, CALCULATE, DIVIDE, variables, filter context and reusable calculation patterns.\npubDate: 2026-09-10\nlabel: Power BI\n---\n\n# <p>DAX can look intimidating when you first start using Power BI, but the basic idea is simple: DAX is the language you use to create calculations that respond to the filters in your report.</p><p>You do not need to memorize hundreds of functions. A small set of patterns will handle a large percentage of everyday reporting requirements.</p><h2>Start with measures</h2><p>For most report calculations, begin with a measure rather than a calculated column. Measures are evaluated based on the current filter context, which makes them ideal for cards, charts, matrices, and KPIs.</p><pre><code>Total Issues =
COUNTROWS(Issues)</code></pre><p>This measure changes automatically when a user filters by date, project, team, or another related dimension.</p><h2>Use SUM, COUNTROWS and DISTINCTCOUNT</h2><p>Three functions cover many common scenarios. Use SUM for numeric values, COUNTROWS for rows, and DISTINCTCOUNT when you need unique entities.</p><pre><code>Total Hours = SUM(Training[Hours])
Total Records = COUNTROWS(Feedback)
Total Participants = DISTINCTCOUNT(Attendance[EmployeeID])</code></pre><h2>Use DIVIDE for ratios</h2><p>DIVIDE is usually safer than the slash operator because it handles zero and blank denominators more gracefully.</p><pre><code>Issues per Inspection =
DIVIDE([Total Issues], [Total Inspections])</code></pre><h2>Understand CALCULATE</h2><p>CALCULATE is one of the most important DAX functions because it evaluates an expression under a modified filter context.</p><pre><code>Open Issues =
CALCULATE(
    [Total Issues],
    Issues[Status] = "Open"
)</code></pre><p>The first argument is the calculation, and the remaining arguments change the filters applied to it.</p><h2>Use variables to make DAX easier to read</h2><p>Variables make complex measures easier to understand and troubleshoot.</p><pre><code>Issue Rate =
VAR IssueCount = [Total Issues]
VAR InspectionCount = [Total Inspections]
RETURN
    DIVIDE(IssueCount, InspectionCount)</code></pre><h2>Learn filter context before advanced functions</h2><p>Many DAX problems are really filter-context problems. When a measure gives the same result for every row, check relationships and filters before adding more functions.</p><p>Functions such as ALL, REMOVEFILTERS, ALLEXCEPT, FILTER, and CALCULATE can deliberately change filter context, so use them carefully.</p><h2>Test measures in a matrix</h2><p>When a calculation is not behaving as expected, add the measure to a simple matrix with the dimension you are analyzing. Seeing the result by month, project, category, or team usually makes the issue much easier to diagnose.</p><h2>Build reusable measures</h2><p>Instead of repeating the same logic, create base measures such as Total Issues, Total Inspections, Total Participants, or Total Hours. Then build higher-level calculations on top of those measures.</p><p>This creates a cleaner semantic model and makes future changes much easier.</p><h2>Final thoughts</h2><p>Good DAX is not about making formulas complicated. Start with simple measures, understand the filter context, use CALCULATE when you need to change that context, and build reusable calculations. Once these foundations are comfortable, advanced DAX becomes much easier to learn.</p>\
